## 1. 개요

PCB 부품 8종 검출에 torchvision Faster R-CNN을 학습하고 평가한 실험입니다. 같은 데이터로 학습한 YOLO, RTMDet(`../rtmdet/`)과 비교하는 것이 목적입니다.

클래스 순서는 RTMDet과 같고, 학습 json의 category_id 1~8과 일치해야 합니다 (`config.CLASSES`, 노트북에서 자동 검사).

```
black_wire, capacitor, ic_chip, led, red_wire, resistance330, resistance470, white_wire
```

4. 결과는 드라이브 `pcb-aoi/faster_rcnn/results/`에 저장되므로, 저장소의 `results/`로 옮겨 커밋합니다.

**로컬**: `pip install -r requirements.txt` 후 이 폴더에서 노트북을 엽니다. 가중치는 공유 드라이브(TODO: 링크)에서 받아 `outputs/`에 넣습니다.

**실행 순서**
- 평가만: `test.ipynb`를 위에서부터 실행

**학습 설정**

| 항목 | 값 |
|---|---|

| 입력 크기 | torchvision 기본값 (짧은 변 800, 긴 변 최대 1333으로 모델 내부 리사이즈) |

| 학습 시간 | 에폭당 약 23초, 전체 약 12분 (T4) |

## 5. 결과

가중치 `best_fasterrcnn_20260923_1007.pth` 기준. 혼동행렬 기반 지표(P/R/F1, 분류 정확도, 검출률)는 IoU ≥ 0.5, 신뢰도 ≥ 0.5로 매칭한 값입니다.

| 지표 | 구 테스트 (8장) | 새 테스트 (22장) |
|---|---|---|
| 정답 박스 수 | 99 | 155 |
| mAP50 | 0.982 | 0.161 |
| mAP50-95 | 0.721 | 0.084 |
| mAR100 | 0.773 | 0.209 |
| Precision (macro) | 0.938 | 0.207 |
| Recall (macro) | 0.942 | 0.290 |
| F1 (macro) | 0.937 | 0.239 |
| 분류 정확도 | 0.960 | 0.789 |
| 검출률 | 1.000 | 0.368 |
| 추론 평균 / 최대 (ms, T4) | 111.9 / 115.7 | 102.5 / 153.0 |

- **분류 정확도**: 위치를 맞게 찾은 박스 중 클래스까지 맞은 비율. **검출률**: 전체 정답 중 위치를 찾아낸 비율(클래스 무관).
- 추론 시간은 이미지 한 장, 배치 1, 워밍업 5회 후 50회 측정. 모델 내부 리사이즈를 포함하고 이미지 디코딩은 제외합니다.
- 클래스별 AP와 혼동행렬은 `results/*.json`에 있습니다.

**가중치 소실과 재학습**: 초기 학습(2026-09-23, seed 없음)의 가중치 `best_fasterrcnn_20260923.pth`는 소실되어, 같은 설정에 seed 42를 고정해 재학습했습니다. 초기 가중치의 결과는 구 테스트 mAP50 0.969, 새 테스트 mAP50 0.165, 분류 정확도 0.81, 검출률 0.37로 재학습 결과와 거의 같습니다. 구 테스트 mAP50-95는 세 번의 학습에서 0.715, 0.683, 0.721이었습니다 (TODO: 초기 두 번이 구 테스트 기준인지 확인).

## 6. 관찰과 결론

**새 촬영 조건에서 크게 떨어진다**
- 구 테스트에서 mAP50 0.982였지만 새 테스트에서는 0.161입니다. 세 번의 학습 모두 같은 양상이라 학습 한 번의 운이 아닙니다.
- 새 테스트의 정답 155개 중 위치를 찾은 것은 57개(검출률 0.37)입니다. 반면 정답과 겹치지 않는 예측(오검출)이 132개로, 맞게 찾은 45개의 3배 가까이 됩니다.

**찾은 것은 대체로 맞히지만, 저항 두 종류를 구분하지 못한다**
- 찾은 57개 중 45개는 클래스까지 맞았습니다(분류 정확도 0.79). 틀린 12개 중 11개가 resistance470을 resistance330으로 부른 경우입니다.
- 새 테스트에서 resistance470은 정답 20개 중 하나도 맞히지 못했고, 모델이 resistance470으로 예측한 박스 자체가 없습니다. 구 테스트에서도 틀린 4개가 모두 두 저항 사이의 혼동이었습니다. 두 저항은 색 띠로만 구별되므로 조명·색감이 바뀐 새 촬영 조건에 특히 약한 것으로 보입니다.

**과적합**
- train 손실은 1.58에서 0.085까지 계속 내려갔지만, valid 손실은 13 에폭(0.698)이 최저였고 이후 0.80까지 올랐습니다. 학습 65장으로는 일반화할 만큼의 다양성이 부족합니다.

**판단**
- 원인은 모델 구조보다 학습 데이터(65장, 한 가지 촬영 조건)의 양과 다양성 부족으로 판단해 실험을 중단하고 YOLO로 진행합니다.

**한계**
- 학습에 데이터 증강을 쓰지 않았습니다. YOLO는 기본 설정에서 mosaic, 색상·크기 변화, 뒤집기를 적용하므로, 새 촬영 조건에서의 성능 차이에는 증강 여부가 섞여 있을 수 있습니다. 특히 색 변화 증강은 저항 구분에 영향을 줄 수 있습니다.
- 학습 이미지(684×386, Roboflow 전처리)와 새 테스트 이미지(4224×3168 원본)는 해상도와 가로세로 비율이 달라, 모델 내부 리사이즈 후 부품의 상대 크기가 달라질 수 있습니다.
- 테스트셋이 8장, 22장으로 작아 수치의 오차가 큽니다.
- 체크포인트를 검증 mAP가 아니라 검증 손실(train 모드에서 계산, 샘플링 노이즈 있음)로 골랐습니다.

**후속 과제**
- YOLO도 새 테스트 22장으로 평가해야 합니다. YOLO도 크게 떨어지면 데이터 한계라는 판단이 강해지고, 버틴다면 증강 등 학습 설정의 영향일 가능성이 큽니다.
- YOLO에서도 resistance330/470 혼동이 나타나는지 확인합니다. 나타난다면 두 저항의 학습 데이터를 우선 보강해야 합니다.
