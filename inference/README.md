# 추론 서비스 (Python)

- 담당: 
- 기술: Python, FastAPI, YOLO
- 포트: 8001

스테이션(C#)이 정렬된 보드 이미지를 보내면, **어느 핀홀에 어떤 부품이 꽂혀 있는지**를
반환한다. 장착 상태가 맞는지 틀린지 "판정"(PASS/FAIL)은 하지 않는다 — 그건 스테이션의 몫이다.
모델 가중치와 데이터셋은 Git에 올리지 않는다.

API 계약(요청/응답 형식)은 [docs/api-contract.md](../docs/api-contract.md) 참고.

## 처리 흐름

이미지 한 장이 들어와서 `{pinhole, class, confidence}` 목록이 나가기까지, 4단계를 거친다.

```mermaid
flowchart TD
    IMG[이미지 JPEG] --> DECODE[0. 디코딩 + 회전 + 크롭<br/>roi.crop_to_roi<br/>세로: 고정값 · 가로: 레일 선 검출 + 중앙 단위 선택]
    DECODE --> DETECT

    subgraph S1["1. 홀 검출 (완성)"]
        DETECT[board_detect.find_pinhole_pixels<br/>홀 blob 검출 → 열은 간격 기반 그룹핑(실측값),<br/>행은 모든 열을 합쳐 y=b0+b1·행번호+b2·x<br/>평면 하나로 최소제곱 계산 (이미지 변형 없음)]
    end

    DETECT --> HOLES[282개 Hole 객체 생성<br/>board.all_holes_from_image]
    DECODE --> YOLO

    subgraph S2["2. 부품 탐지 (TODO)"]
        YOLO[크롭된 이미지로 YOLO 탐지<br/>픽셀 사각형 + 종류·신뢰도]
    end

    HOLES --> MATCH[3. 홀-박스 대조<br/>board.match_holes_to_boxes<br/>홀 위치가 박스 안에 들어가면<br/>그 홀 = 가려짐 장착됨]
    YOLO --> MATCH
    MATCH --> OUT[가려진 홀만 추려서<br/>parts 배열로 응답]
```

**왜 이런 순서인가**
- 카메라가 눕혀서 찍기 때문에, 크롭 전에 먼저 왼쪽(반시계) 90도로 돌린다 (`roi.ROTATE`).
- 카메라·촬영 지그가 고정돼 있어서, 보드가 세로(행) 방향으로는 이미지 안에서 대략 어디쯤 나오는지 항상 같다 — 그래서 세로 범위(`roi.Y_RANGE`)는 고정값이다.
- 하지만 실측해보니 가로(열) 방향은 사진마다 레일 선 위치가 40px 넘게 달라졌다 (카메라가 살짝씩 밀림). 그래서 가로는 고정 숫자로 자르지 않고, **매번 빨강/파랑 전원 레일 선을 색으로 찾아서**(`rail_detect.py`) 후보 단위들을 찾는다. 딥러닝이 아니라 HSV 색상 임계값 기반의 전통적 머신비전이다.
- 프레임 안에 이런 "레일-단자부-단자부-레일" 단위가 여러 개 있으면(테스트 사진처럼 보드가 여러 개 같이 찍힌 경우), **프레임 중앙에 가장 가까운 것을 고른다** (`find_center_unit_x_range`) — 카메라·지그가 고정돼 있으면 검사 대상 보드는 항상 중앙 부근에 놓인다는 가정. "부품이 많아 보이는 곳"(edge 밀도, `find_populated_unit_x_range`)보다 부품 개수·조명에 안 흔들려서 더 안정적이다. 실제 검사 라인처럼 보드가 하나뿐이면 후보도 하나뿐이라 결과는 똑같다.
- 크롭 후에도 보드 위치·기울기·크기가 더 미세하게(픽셀 단위로) 조금씩 다르다. 그래서 핀홀 픽셀 위치를 고정값으로 하드코딩할 수 없고, **크롭된 이미지마다 다시 계산**해야 한다.
- 처음엔 네 모서리 핀홀 픽셀 좌표만 찾아서 `calibration.py`의 호모그래피로 나머지 278개 위치를 선형보간하려 했는데, **실측해보니 부정확했다** — 이 브레드보드는 열 6~7 사이에 단자부 채널(물리적으로 넓은 갭)이 있어서 열 간격이 균등하지 않은데, 모서리 4개짜리 단일 호모그래피는 균등한 간격을 가정하기 때문이다. `calibration.py`는 이 한계 때문에 레거시로 남아있다 (calibration.py 문서 참고).
- 그다음엔 네 모서리로 원근 변환(perspective warp)해서 기울기(회전)만 이미지를 평면처럼 편 다음 검출하는 방법도 시도했는데, 부품이 많은 사진(`board1.jpg`)에서 실측해보니 **오히려 왜곡이 더 커졌다**. 그래서 지금 `board_detect.py`는 **이미지를 아예 변형하지 않는다.**
- 행 위치를 구할 때 두 가지 버그를 실측으로 잡았다. ① 레일 열(0,1,12,13)은 E/K/Q 행이 빠져서 18칸인데, 이걸 그냥 "17칸 균등 간격"으로 나누면 틀린다 — D-F, J-L, P-R 사이는 (건너뛴 자리만큼) 물리적으로 2칸 너비라서 진짜 물리적 간격은 20칸이다. `pinhole_grid.ROWS`(A~U, 21개) 안에서의 실제 인덱스를 기준으로 계산하도록 고쳤다. ② 처음엔 **열마다 따로** 그 열 자신의 첫 홀~마지막 홀 사이를 선형보간했는데, "같은 알파벳(행)의 핀홀은 항상 일직선이어야 한다"는 물리적 제약을 이 방식이 구조적으로 보장하지 못했다 — 열마다 독립적으로 계산하다 보니 같은 행이라도 열마다 y값이 살짝 어긋날 수 있었다 (`board1.jpg`에서 실측 확인됨). 그래서 지금은 **모든 열의 모든 홀을 한꺼번에** 써서 `y = b0 + b1*행번호 + b2*x` 평면 하나를 최소제곱으로 피팅한다 — 평면 하나로 모든 위치를 계산하므로 같은 행번호는 정의상 항상 일직선이 된다. (WORKLOG.md 참고) 두 사진 모두 레일 열까지 포함해 픽셀 단위로 정확히 맞는 것까지 확인됨.
- "박스 중심과 가장 가까운 핀홀 하나"를 고르는 대신, 반대로 "핀홀마다 어떤 박스 안에 들어가는지"를 본다. 이러면 저항처럼 다리(핀) 두 개짜리 부품이 핀홀 두 개에 걸쳐 있어도 둘 다 자연스럽게 잡힌다.

## 파일 구성

| 파일 | 역할 | 상태 |
|---|---|---|
| [app/main.py](app/main.py) | FastAPI 앱. `/health`, `/infer` 엔드포인트 | 뼈대 완성, TODO 1곳 남음 |
| [app/roi.py](app/roi.py) | 원본 이미지를 회전(왼쪽 90도) 후, 세로는 고정값·가로는 레일 선 검출 + 중앙 단위 선택으로 크롭 | 완성 (실제 사진 2장으로 검증됨) |
| [app/rail_detect.py](app/rail_detect.py) | 빨강/파랑 전원 레일 선을 HSV 색상으로 찾아 가로 크롭 범위 계산. 후보가 여럿이면 프레임 중앙에 가장 가까운 것 자동 선택 | 완성 |
| [app/pinhole_grid.py](app/pinhole_grid.py) | 핀홀 282개의 그리드 정의(행 A~U, 열 0~13)와 라벨 변환 | 완성 |
| [app/board_detect.py](app/board_detect.py) | 크롭된 이미지에서 홀을 직접 검출 → 열은 간격 기반 그룹핑, 행은 모든 열을 합친 평면(y=b0+b1·행번호+b2·x) 최소제곱 피팅 → 282개 핀홀의 실제 픽셀 위치 계산 (이미지 변형 없음) | 완성 (실제 사진 2장으로 검증됨) |
| [app/calibration.py](app/calibration.py) | (레거시) 네 모서리 핀홀 픽셀 좌표 → 호모그래피 → 픽셀 ↔ 그리드 좌표 변환. 열 간격 비균등 문제로 부정확해서 board_detect.py로 대체됨 | 레거시 |
| [app/board.py](app/board.py) | 핀홀 282개를 이미지 속 위치·장착 여부와 함께 구조화, YOLO 박스와 대조 | 완성 |

## 아직 안 된 것 (TODO)

> `roi.Y_RANGE`(세로 고정값)는 지금 테스트에 쓴 특정 카메라·거치대 기준값이다. 실제 검사 라인의 카메라·지그로 바뀌면 다시 맞춰야 한다. 가로는 `rail_detect.py`가 매번 다시 찾으므로 카메라가 조금 움직여도 괜찮다.
>
> 참고: 테스트 사진처럼 책상에 브레드보드가 여러 개 나란히 놓여 있어도, `crop_to_roi()`는 그중 프레임 중앙에 가장 가까운 것을 스스로 골라낸다 (`find_center_unit_x_range`). 카메라·지그가 고정이라 검사 대상 보드가 항상 중앙 부근에 온다는 가정이며, 부품 개수·조명에 흔들리지 않는다. 실제 검사 라인은 지그에 보드가 하나만 고정되므로 애초에 후보가 하나뿐이라 이 문제 자체가 없다.
>
> `board_detect.py`의 홀 검출은 실제 사진(부품 없는 보드, 부품 많은 보드) 둘 다에서 검증됐다 — IC·LED·커패시터로 홀이 가려져도 정렬이 유지된다. (원근 변환으로 이미지를 평탄화하는 방법도 시도했는데, 부품 많은 사진에서 렌즈 왜곡을 오히려 증폭시키는 걸 확인하고 뺐다 — WORKLOG.md 참고.)
